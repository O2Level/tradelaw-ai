# CODEX Mission: TradeLaw AI MVP

你是本仓库的全栈产品工程 Agent。你的任务是把 `docs/product/TradeLawAI-plan.docx` 中的 TradeLaw AI 计划落地为一个可运行、可演示、可复核、可导出报告的真实 MVP 产品。

## 一、最高目标

在本仓库中交付一个真正能跑的 TradeLaw AI Web 工作台，面向中国中小外贸企业出口东南亚订单场景。产品必须完成以下闭环：

1. 订单建档或案例导入
2. 合同、PO、PI、聊天摘要、单据材料上传或文本导入
3. 抽取订单关键字段
4. 基于规则库识别红黄绿风险
5. 输出风险解释、原文条款、修改建议、人工复核要求
6. 红色风险进入法务、负责人或律师复核流程
7. 履约节点留痕，提示证据缺口
8. 导出业务员版、负责人版、法务版、证据包摘要
9. 所有核心动作必须有数据库状态变化、可见 UI 反馈、可复测结果

禁止只做漂亮页面。禁止只做静态 mock。禁止硬编码一个单一报告。禁止按钮没有真实动作。禁止用“coming soon”覆盖 MVP 核心功能。

## 二、计划包约束

你必须读取 `docs/product/TradeLawAI-plan.docx`。若无法直接解析 docx，则在仓库中创建 `docs/product/PLAN_EXTRACT.md`，并基于下面的强制摘要继续执行：

产品定位：
TradeLaw AI 是面向中国中小外贸企业出口东南亚订单的法律风险协作工作台。MVP 以 Web 平台为主，重点做订单空间、合同/PO/PI 风险审查、履约留痕、人工复核、报告导出。

MVP 做：
1. 合同、PO、PI 上传或文本导入
2. 抽取主体、金额、产品、数量、目的国、贸易术语、付款节点、交期、验货方式、争议解决条款
3. 基于规则库输出红黄绿风险报告
4. 高风险事项进入人工复核并留痕
5. 导出 Word 或 PDF 风险报告和证据包摘要
6. 准备越南、印尼、马来西亚或菲律宾演示案例

MVP 暂缓：
1. 实时客户信用判断
2. 真实制裁名单、负面舆情、企业数据库自动命中
3. 深度接入真实 CRM、ERP、邮箱、WhatsApp、微信、飞书
4. 越南、印尼、马来西亚本地正式法律意见
5. 完整私有化部署和大型企业权限体系

## 八、种子规则库

创建至少 25 条种子规则，覆盖以下类型：

1. 付款风险
到港后付款、转售后付款、客户验收后付款、未约定逾期付款责任、尾款比例过高、首次合作客户付款保护不足。

2. 交付与贸易术语风险
DDP 下未明确进口清关、税费、滞港费、目的国资料责任；FOB/CIF/EXW 责任边界不清；客户指定货代且单据控制不足。

3. 验货和质量异议风险
未约定验货期限、异议期限、验货标准、第三方检验机制、逾期默认验收规则。

4. 争议解决风险
未约定适用法律、争议解决方式、仲裁地、法院管辖、语言。

5. 单据和证据风险
缺少提单、装箱单、发票、质检报告、收货确认、催款记录、发货通知。

6. 版本一致性风险
合同、PO、PI、邮件确认中的价格、数量、交期、贸易术语不一致。

7. 东南亚目的国交易注意事项
越南尾款与验货风险
印尼 DDP 清关和税费风险
马来西亚质量异议和拒付风险
菲律宾收货确认和尾款风险
泰国目的港费用风险
新加坡争议解决条款规范性提示

规则字段必须包括：
`ruleId`
`riskType`
`scenario`
`trigger`
`severity`
`businessExplanation`
`suggestedRevision`
`requiredMaterials`
`requiresHumanReview`
`source`
`lastUpdated`

至少实现 R-PAY-001：
触发条件包含 `balance paid after arrival`、`after resale`、`after buyer inspection` 等表述，且无信用证、担保、提单控制或逾期付款责任。
风险等级为红色。
建议包括发货前付清尾款、凭提单副本付款、信用证付款、补充逾期付款责任、暂停发货权利。

13. 复核人必须能写入意见。
14. 复核意见必须保存到数据库。
15. 重新打开订单后复核意见仍然存在。
16. 导出负责人版报告。
17. 导出法务版报告。
18. 报告文件必须真实存在。
19. 报告中必须包含免责声明。
20. 修改付款条款为 `shipment before balance paid` 或 safer equivalent 后重新扫描，风险结果必须发生变化。

任何一步失败，都不得宣称 MVP 完成。

## 十九、自主迭代轮数调整

把原来的最多 6 轮调整为最多 12 轮。

第 0 轮：读取计划包、盘点仓库、确认本地和 GitHub 状态、创建分支、写执行计划。

第 4 轮：实现字段抽取和材料导入，文本粘贴必须稳定。
第 5 轮：实现订单空间、风险扫描、风险报告页。
第 6 轮：实现人工复核、审计日志、证据时间线。

## 二十、质量门和退出条件
